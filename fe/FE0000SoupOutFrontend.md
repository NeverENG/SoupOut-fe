# M01 职责边界

| 归前端 | 归服务端 |
|---|---|
| 渲染、动画、VFX、镜头 | 权威模拟、命中判定、状态裁决 |
| **客户端预测**（本地立即响应输入） | 房间、tick、地盘计算 |
| **和解 / 回滚重放** | 面积统计与结算 |
| 远端玩家插值与外推 | 匹配、房间码 |
| 输入采集与上报（含冗余） | —— |
| 全流程 UI、音频 | —— |

**一句话**：**服务端说什么是真的，前端负责让它看起来不卡。**

# M05 前端最容易做错的八件事【硬约束速查】

> 每一条都不是打磨，是正确性。做反了要返工。

### ① 挥舞立即播，命中等服务器
挥舞前摇的音效和 VFX **按下就播**，不等服务器；命中的音效、顿帧、震屏**等服务器确认**。
反过来做 = 把 RTT 塞进打击感里。（`T0001M04F01` · `A0001M02F04`）

### ② 只预测自己向原汤的扩张，不预测争议边界
「按住看它涨」是核心爽点，等不起 RTT，所以本地按同样的 `expandRate` 乐观推进。
但**顶到敌方地盘时停下**——你不知道对面有没有在充能，那是服务端的裁决。（`T0001M04F01/F02`）

### ③ 输入上报的是「按住状态」，不是「开始/结束事件」
`buttons.bit1` 每帧如实上报当前按键状态。
**不要发"开始充能/结束充能"事件**——事件丢了会卡在错误状态，而按住状态每帧自愈。（`T0001M02F04`）

### ④ 输入包必带 3 帧冗余 + 两个 baseline 回传
`PlayerInput` 携带最近 3 帧（丢 1–2 个包无感），并回传 `lastRecvSnapshotTick` 与 `lastRecvTerritoryTick`。
**后者不回传，服务端的累积增量永远裁剪不掉，包会越来越大。**（`T0001M02F04` · `M03F06`）

### ⑤ 地盘不直接画格子
96×96 → marching squares 抽等值线 + 轻度平滑。新翻转的格做 **150ms 漫开渐变**掩盖 10Hz 的离散感。
边缘保留轻微像素颗粒——**这正好是马赛克基调，不是妥协**。（`T0001M03F08` · `A0001M04F04`）

### ⑥ 角色必须能跨 10%–65% 缩放
体型跨度 2.3×。矢量缩放要单独控制线宽和眼睛比例，否则大号糊、小号眼睛占满脸。
**方案（矢量 vs 3–4 档体型）在 P0 里就要试出来**，定晚了角色美术整套重做。（`A0001M04F02`）

### ⑦ 五色必须色盲可辨，并加纹理做第二重区分
4 玩家色 + 原汤色，必须过红绿色盲校验。**读错颜色 = 读错局势。**
暖色基调下凑 4 个高区分度的色本身就难，这是配色阶段的主要约束。（`A0001M04F03`）

### ⑧ 平板外放的现实
力量感全放 **300 Hz–4 kHz**（低频听不见）· SFX **全单声道** · **SFX voice 上限 16** · 自己的音效永远抢占别人的。（`A0001M02`）

# M07 现在该做什么

**P0 原型，3 周，时间盒。** 验收标准见 `../V0001SoupOutP0.md`。

要回答的只有两个问题：
1. **按住把汤铺出去、角色跟着变大——爽不爽？**
2. **绕板子、翻窗——在 2D 俯视 + 平板触屏上拉不拉得起来？**

两条提醒：

- **调参面板必须做**（`V0001M02F01` 第 9 条）。没有它，P0 只能验出「爽不爽」，验不出「多少才爽」——后者才是 P0 真正的产出
- **`A3`（爽度中位数 ≥ 4）是全项目唯一的 Pivot 触发条件。** 低于 3 分就停，不要"再调调"
